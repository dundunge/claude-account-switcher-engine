# IPv6 代理绕过与额度查询失败事件记录

日期：2026-10-28（America/Los_Angeles）。本记录仅保存脱敏事实，不包含真实公网出口、账号身份、凭据或访问令牌。

## 结论

关闭 Clash/Mihomo 的 IPv6，并不等于关闭 macOS 的 IPv6，也不保证所有 Claude 客户端只通过固定出口访问网络。

本次关闭 Clash IPv6 后，系统仍能解析和路由 IPv6；已检查的目标 IPv6 路由走物理网卡而非 Clash TUN。Claude Desktop 出现地区不可用提示；开启系统代理后用户确认桌面端恢复。CASE 的独立 Claude Code 额度查询没有自动获得同样的代理设置，三个账号均显示 `CLI_USAGE_UNAVAILABLE`。

同账号对照查询显示：原环境发生直连 IPv6 连接且额度请求返回 HTTP 403；仅给测试进程显式配置现有本机代理后，额度请求成功。该结果支持代理绕过是本次故障原因，但没有逐条关联套接字、请求与响应，不能断言每一次 403 均由 IPv6 直连返回。

## 事件经过与证据

1. 先前静态 ISP 排查发现：同一代理对目标 IPv4 的 CONNECT 成功，对目标 IPv6 字面地址的 CONNECT 返回 502。代理接入端另有 429/超时问题；这些不是本次额度 HTTP 403 的同一类证据，不能混为一谈。
2. 为避开上述 IPv6 502，关闭了 Clash 全局 IPv6 和 DNS IPv6。后续检查发现 macOS 的系统解析仍可返回 IPv6，且目标路由绕过 TUN。
3. Claude Desktop 出现地区不可用提示。不带账号的 IPv6 公开页面测试跳转到地区不可用页面；经本机代理的对照没有同样跳转。用户开启系统代理后确认桌面端能进入。
4. CASE 界面三个账号均显示 `CLI_USAGE_UNAVAILABLE`。单账号官方 CLI 诊断确认实际发起额度请求并得到 HTTP 403；不是仅仅未解析到 UI 数字，也不能据此认定登录过期。
5. 同账号对照：

   | 条件 | 可观察结果 |
   | --- | --- |
   | 原环境，无继承的代理变量 | 观察到目标 IPv4、IPv6 连接；额度请求 HTTP 403，查询失败 |
   | 测试子进程显式指定现有本机 HTTP 代理 | 观察到本机代理连接；官方新请求成功，查询成功 |

6. 修复 CASE 的 CLI 环境构造后，三个账号均取得新读数；安装后的应用点击一次“刷新全部”，界面报告三个账号刷新成功，各自显示两档额度、重置时间和“刚刚查询 · 官方 CLI”。

早先“只关闭 Clash IPv6 就够了”的判断不完整：它解决代理对 IPv6 目标的兼容问题，但没有覆盖系统原生 IPv6 的绕行路径。系统代理恢复桌面端，也不能直接证明 CLI 已使用代理。

## 公网 IP 暴露风险与不确定性

- 原生 IPv6 直连的远端服务或边缘基础设施可以观察请求的公网源 IPv6，并可能据此判断地区。不能将本次描述为“没有暴露真实出口”。
- 公开页面探测不带账号；官方 CLI 额度查询则使用账号授权。因此，额度查询绕过代理时存在将直连出口与账号关联的风险。
- 诊断期间曾复现原环境的查询路径，可能增加了直连请求；不能把排查描述为零网络暴露。以后应先检查解析、路由和代理环境，再决定是否需要带账号对照。
- 尚无证据证明 Anthropic 实际记录了哪些字段、保留多久、是否关联账号或触发风控；也没有账号被处罚的证据。地区提示和 403 本身不足以证明处罚。
- 没有逐条抓取桌面端当次请求，不能断言该次携带了哪些身份信息；也没有逐条将 CLI 403 绑定到已观察的 IPv6 套接字。
- 本次没有主动上传 Clash 配置、代理密码、账号令牌或 Codex 聊天内容。源 IP 可见与泄露配置/凭据不是同一件事。
- 修复只能改变之后的查询路径，不能撤销此前可能产生的服务端记录。

## 修复范围

本地修改 `tools/claude_usage_probe.py` 的环境构造：

- macOS 上，未继承显式 HTTP(S)/ALL_PROXY 环境变量时，读取当前已启用的系统 HTTP/HTTPS 代理并传给官方 CLI。
- 已有代理环境变量优先，保留 `NO_PROXY`；不硬编码代理端口，不执行 PAC，不读取代理认证凭据。
- 不修改 macOS 或 Clash 网络设置，不重载 Clash，不切换账号、不重新授权、不重启 Claude。
- 其他平台保持原有行为；只启用 TUN、未开启系统 HTTP/HTTPS 代理时，不会凭空添加代理。

该修复不是系统级防泄漏或 fail-closed 保证。系统代理被关闭、显式代理/排除变量改变、其他客户端采用不同网络栈，都需要重新核验实际路径。不能把三个账号查询通过推广为所有 Claude 流量均不会直连。

## 后续操作原则

1. 先核对 DNS、IPv4/IPv6 路由、客户端实际代理环境，不能以开关状态代替连接证据。
2. 不默认用带账号请求反复复现疑似直连；优先本地只读检查和不带账号的最小网络测试，明确其暴露公网 IP 的风险。
3. 网络路径变化后分别验证 Desktop 和 CLI，使用少量查询，不靠旧缓存判定成功。
4. Claude 相关进程或已知网页会话活动时禁止重载 Clash/Mihomo；不得自行退出或终止 Claude 来绕过限制。
5. 如需回滚 CASE，正常退出 CASE 后恢复备份应用；回滚应用不会自动修复网络路径，需重新核验额度查询。

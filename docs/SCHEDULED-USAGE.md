# 可选定时刷新额度

## 使用

进入 **设置 → 额度查询 → 定时刷新额度**。默认关闭，默认间隔为 2 小时。

- 输入分钟或小时，点击“保存间隔”，或选“2 小时”“5 小时”快捷按钮。
- 支持 **5 分钟至 7 天**，精确到整分钟；例如 `95 分钟` 或 `1.5 小时`。
- 保存间隔不会自行开启。打开开关后从现在计时，显示带本机时区的下次刷新时间。
- 开启或修改间隔不立即查询；需要当前读数时仍可在主页刷新单号或全部账号。
- 建议每 2 或 5 小时刷新。仅执行官方 CLI `/usage`，不发送模型聊天提示词；
  官方服务仍可能限流或不可用，CASE 不保证每次请求成功。

## 执行规则

一个 Rust 后端 worker 负责计时，打开或关闭设置窗口不会创建新计时器。
CASE 隐藏在菜单栏时继续运行；退出 CASE 后没有系统定时任务，也不会另行唤醒电脑。
已开启的配置和下次时间会保留。电脑唤醒或 CASE 重新打开时，若已过期，最多执行一轮，
不补发每个错过的周期；下一次从本轮开始时重新计时。到期后通常在 15 秒内开始检查。

每轮按账号列表串行处理，逐个重新确认账号仍存在：

- 仅查询完成独立授权且 Desktop profile、account/org 与绑定匹配的账号。
- 跳过未授权、身份不匹配、已知需重新登录或首次设置未完成、正在查询的账号。
- 本次 CASE 运行中，在当前间隔内已经尝试过的账号也会跳过，避免手动刷新后很快重复查询。
- 失败后继续其他账号，本轮不立即重试；一般查询故障可在下周期再尝试。
- 已知授权或首次设置信息阻塞时，需先由用户在设置中处理，再手动查询验证。
- 关闭或改变设置后，当前查询正常收尾，本轮不继续剩余账号；下次按新设置计时。

开始前先原子保存下次时间，保存失败则不发起本轮查询，并在设置中报告。
缺失、无效或异常超前的时间会重新计时，不直接请求。设置页显示运行状态与上轮成功、未获取、跳过数量。

## 数据和授权边界

设置保存在 CASE 原有的 `accounts.json` 的 `settings.usageSchedule` 中：

```json
{
  "enabled": false,
  "intervalMinutes": 120,
  "nextAt": null
}
```

新增字段缺失或损坏时容错关闭，不丢弃账号列表。间隔同时在前端和后端校验。
关闭后可随时继续手动查询，删除新配置字段也会恢复默认关闭。

定时刷新复用手动查询的官方 CLI 路径、身份检查和超时约束，不读取 Desktop 凭据，
不打开授权窗口或 Terminal，不触发原生面板读取，不切号或退出当前 Desktop。
独立 `--user-data-dir`、account/org 绑定与六种结果状态保持不变。
真正开始查询时清空当前值；失败仍返回 `usage: null`，不会恢复旧百分比。
仅被跳过的账号不会产生查询或新的失败状态。
